# 엣지 케이스 목록 (구현 전 작성)

## 이 문서는 무엇인가

BANG! 은 규칙이 단순해 보이지만, 실제로는 **"카드 사용 도중에 다른 카드 사용이 끼어드는"** 구조 때문에
엔진을 순진하게 짜면 반드시 무너진다. 이 문서는 코드를 쓰기 **전에** 그 무너지는 지점을 미리 모아 둔 것이다.
각 행은 그대로 하나의 회귀 테스트가 되며, 엔진 설계(상태 머신·훅·프레임 스택)의 요구사항을 역으로 규정한다.

### 원본 자료의 성격과 한계

주 자료는 `reference/sc2-arcade/analysis/new_strings_by_version.json` —
StarCraft II 아케이드 "뱅!" 맵의 2014~2025년 144개 버전 신규 문자열이다.
대부분이 패치노트이며, **11년간 실제 온라인 플레이에서 터진 버그의 목록**이라는 점에서 가치가 크다.
룰북은 "무엇이 옳은가"를 말하지만, 이 패치노트는 "무엇이 실제로 틀리게 구현되는가"를 말한다.

한계도 분명하다.

1. **문자열 diff라서 문맥이 잘린다.** 한 항목이 여러 줄로 이어지는데 앞뒤가 끊긴 것들이 있다
   (예: 0.42 `"맥주를 통하여 죽음의 위기에서 탈출할때, "` 는 다음 줄이 소실됨). 이런 건 추정을 명시했다.
2. **원문에 오타가 많다.** (`낼 수 업도록`, `"Dynamite"릉`, `능력ㅇ르`) 인용은 오타 포함 그대로 옮겼다.
3. **확장판이 6개나 섞여 있다.** 이 프로젝트는 기본판 + 하이 눈만 구현하므로,
   확장 전용 케이스는 문서 끝 부록으로 분리했다. 단 **확장 요소가 기본 요소의 취약점을 드러낸 경우**
   (예: 베라 커스터가 벌쳐 샘을 복제 → 벌쳐 샘의 탈락 시 카드 분배 로직 자체가 부실하다는 증거)는
   기본판 교훈으로 바꿔 정식 케이스로 등재하고 근거 원문을 함께 적었다.
4. **이 맵의 구현이 항상 옳지는 않다.** 제작자 스스로 0.121에서 "공식 규칙이 아닌 것 3가지"를 고백했다.
   패치노트가 원작 룰과 충돌하는 항목은 마지막 절 「애매해서 결정이 필요한 항목」으로 뺐다.

### 읽는 법

- 카드/캐릭터/이벤트 id는 `src/game/data/cards.base.ts`, `cards.highnoon.ts`, `characters.ts` 의 실제 id다.
- 카드 인스턴스 id는 `<kind>-<무늬코드><숫자>` (예: `dynamite-h2`, `jail-s10`, `barrel-sQ`).
- 「기대 결과」는 반드시 단언(assert) 가능한 문장으로 적었다.

## 설계에 주는 교훈

1. **판정(카드 펼치기)은 함수가 아니라 프레임이어야 한다.**
   판정 중에 러키 듀크의 선택이 끼어들고, 별도의 타이머가 붙고, 축복/저주가 무늬를 덮어쓰고, 광클을 막는 멱등성이 필요하다.
   `drawExclamation(): Card` 같은 동기 함수로 만들면 이 넷 중 하나도 넣을 수 없다.
   (EC-10, EC-20, EC-21, EC-22, EC-85, EC-94)

2. **손패가 비는 모든 경로에서 훅이 울려야 한다.**
   수지 라파예트는 사용·장착·반응·버림당함·빼앗김·손패 제한 정리 — 어디서든 손패가 0이 되면 발동한다.
   손패 변경은 반드시 단일 함수를 거치고, 그 함수가 훅을 발행해야 한다. 카드별 코드에서 직접 `hand.splice()` 하면 반드시 새는 경로가 생긴다.
   (EC-51, EC-90, EC-91)

3. **모든 피해에는 `source`(가해자)와 `cause`(원인)가 태그로 붙어야 하고, `source`는 null일 수 있다.**
   현상금 지급, 보안관의 부관 처치 벌칙, 엘 그링고의 카드 탈취, 자해 판정이 전부 이 태그에서 갈린다.
   반대로 바트 캐시디는 태그와 무관하게 발동한다 — 두 종류의 훅이 존재한다는 뜻이다.
   (EC-52, EC-56, EC-57, EC-58, EC-59, EC-61, EC-64)

4. **"뱅! 카드"와 "뱅! 효과"를 타입 수준에서 구분해야 한다.**
   기관총은 뱅! 효과지만 뱅! 카드가 아니다. 그래서 슬랩의 2장 요구를 받지 않고, 설교 중에도 쓸 수 있고,
   "차례당 1회" 카운터를 소비하지 않는다. 반대로 칼라미티 자넷의 빗나감!은 뱅! 카드로 취급되어 카운터를 소비한다.
   (EC-25, EC-28, EC-30, EC-79, EC-96)

5. **무늬는 절대 `card.suit`로 직접 읽지 않는다.**
   축복/저주가 전역으로 무늬를 덮어쓰기 때문에, 판정·블랙 잭 공개·수갑 선언·(확장의) 무늬 기반 능력이
   전부 `effectiveSuit(card, state)` 한 곳을 거쳐야 한다. 한 군데라도 직접 읽으면 그 경로만 축복을 무시한다.
   (EC-94, EC-95, EC-104)

6. **캐릭터 능력은 전역 게이트 뒤에 있어야 한다.**
   숙취는 16종 전부를 한 번에 끄고, 능력이 다시 켜지는 순간(숙취 종료)이 그 자체로 훅 발화 지점이 된다.
   `isAbilityActive(state, player)` 를 각 능력 진입점에서 호출하는 구조여야 하며, 능력 코드 안에 숙취 체크를 흩뿌리면 안 된다.
   (EC-91, EC-92, EC-109)

7. **모든 대기 상태에는 타임아웃과 결정적인 기본 동작이 있어야 한다.**
   온라인 게임에서 이탈은 예외가 아니라 **응답의 한 종류**다. 다중 대상 프레임(기관총·인디언·잡화점)은
   참여자 하나가 사라져도 끝까지 해소되어야 한다. 11년간 이 문제로 나온 패치가 가장 많다.
   (EC-32, EC-41, EC-42, EC-46, EC-110, EC-113, EC-117)

8. **승리 판정은 탈락 이벤트가 아니라 모든 상태 전이 뒤에 호출한다.**
   유령의 차례 종료, 동시 탈락, 유령 무법자의 보안관 처치 — 전부 "탈락 훅"만으로는 잡히지 않는다.
   또한 여러 탈락이 한 프레임에서 일어나면 **모두 처리한 뒤 1회만** 판정해야 중간 상태에서 오판하지 않는다.
   (EC-68, EC-69, EC-70, EC-103)

9. **"생존자 수"와 "링 참여자 수"는 다른 개념이다.**
   맥주의 2인 제한은 생존자 수를, 거리 계산과 잡화점의 카드 수는 링 참여자 수를 본다.
   유령도시가 이 둘을 갈라놓으며, 하나로 뭉뚱그리면 유령의 거리가 0이 되거나 잡화점 카드가 모자란다.
   (EC-01, EC-40, EC-45, EC-47)

  "공격한 사람의 손에서"이므로 가해자가 필요한데, 자기가 시작한 결투에서 진 것은 상대의 공격 행위로 보기 어렵다.

### B. 설교(theSermon) 상황에서 결투를 건 쪽의 응수

  뱅! 카드를 **버리는** 것이지 사용하는 것이 아니다. 그렇다면 설교는 이를 막지 못해야 한다.

- 근거: 원작 룰이 "사용"과 "버림"을 구분하며, 인디언 대응도 같은 "버림"이다.

- 원문: 0.141 "다음차레의 플레이어에게 \"Dynamite\"가 있으면, \"Dynamite\"를 넘기지 않습니다." /
  0.182 "내 다이나마이트가 넘어가지 않은 경우 게임진행이 어려워지던 문제를 수정하였습니다."
- 쟁점: 기본판에는 `dynamite-h2` **1장뿐**이라 이 상황이 원리적으로 발생할 수 없다. 이 패치는 확장 덱(다이너마이트 복수)의 산물이다.
- **권고: 기본판 엔진에서는 "동시에 2장 존재"를 불변식 위반으로 간주해 개발 모드에서 assert 실패시킨다.**
- 근거: 방어 코드로 조용히 넘어가면 카드 유실 버그(EC-72)를 숨기게 된다. (EC-13)

### K. 벌쳐 샘 회수와 현상금 지급의 순서

- 원문: 0.203 "벌쳐 셈과 베라 쿠스터가 목표물의 카드를 번갈아가며 하나씩 가져가며, 제거된 플레이어로부터 시계방향으로 가장 가까운 사람부터 가져갑니다."
- 쟁점: 탈락 시 (1) 벌쳐 샘 회수, (2) 현상금 3장, (3) 보안관 벌칙, (4) 승리 판정의 순서가 원작 룰에 명시되어 있지 않다.
- **권고: (1) → (2) → (3) → (4).**
- 근거: 벌쳐 샘은 탈락자의 카드를, 현상금은 덱을 건드리므로 서로 간섭하지 않지만,
  덱 리셔플 타이밍이 달라지면 리플레이 재현성이 깨진다. 승리 판정은 반드시 맨 마지막이어야
  중간 상태에서 오판하지 않는다(EC-68). 순서를 상수로 고정하고 테스트한다. (EC-63)

### L. 타임아웃 강제 처리 정책 전반

- 원문: 0.36 "타이머가 사라진 직후, 30초내에 새로운 타이머가 생성되지 않으면 강제로 턴이 종료됩니다." /

- **권고: 타임아웃 기본 동작을 게임 규칙의 일부로 명시하고 결정적으로 만든다.**

  (EC-110, EC-117)
