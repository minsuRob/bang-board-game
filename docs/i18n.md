# 번역 (ko · en · it)

## 언어 고르기

- 설정창에서 시스템 / 한국어 / English / Italiano 를 고른다. 기본은 시스템이다 (`src/i18n/lang-store.ts`, 키 `bang.ui.lang`).
- 시스템이면 기기의 첫 번째 선호 언어가 ko·it 일 때 그 언어, 그 밖은 en (`resolve.ts`).
- 웹은 `+html.tsx` 의 `LANG_BOOT` 가 첫 화면 전에 `<html lang>` 을 정한다.

## 구조

```
src/i18n/
  messages/{ko,en,it}/   화면 문구. 이름공간별 파일 (routes table ui codex infra settings common)
  content/{ko,en,it}.ts  카드·캐릭터·이벤트·골드·직업·확장판 이름과 설명
  log/{ko,en,it}.ts      LogMsg → 문장 렌더러
  names.ts, use-names.ts 이름 조회 (순수 namesFor(lang) / 훅 useNames())
  use-t.ts               useT() · getT() · useLang()
  glossary.md            용어집
```

`ko` 가 원본이고 `Messages = typeof ko` 다. en·it 는 `Messages` 로 선언하므로 키가 빠지면 타입 검사가 실패한다.
순수 폴더(engine/data/modifiers/ai/economy)는 `src/i18n` 을 import 하지 않는다 (`boundary.test.ts`).

## 새 문구 넣는 법

1. `messages/ko/<이름공간>.ts` 에 쓴다. 변수가 들어가면 함수로 쓴다. 복수형은 함수 안에서 가른다.
2. en·it 에 같은 키를 쓴다. `glossary.md` 를 따른다.
3. 컴포넌트에서 `const t = useT(); t.<ns>.<key>`. 모듈 최상단 상수에 문구를 넣지 않는다.
4. `npm test && npm run typecheck && npm run i18n:check`.

번역하지 않는 것: 닉네임·채팅 본문, 개발용 데모 문구, `console.warn`, 엔진의 `throw` 메시지.
it 는 공개 배포 전에 원어민 검수를 받는다.

## 검사

- `no-hangul.test.ts`: 번역을 마친 폴더(`ENFORCED`)의 문자열·JSX 에 한글이 있으면 실패한다.
- `npm run i18n:check`: en·it 사전에 한글이 남았거나 ko 와 같은 값이 있으면 목록으로 보인다.
- `resolve.test.ts`, `content.test.ts`, 로그 렌더 테스트.
